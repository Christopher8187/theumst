# Backend architecture

`backend/python/app/main.py` builds FastAPI, installs CORS and compression, mounts public branding images, and includes the routers. `app.py` at the Python root is a compatibility entry; the container uses `app.main:app`.

`routers/frontend.py` serves public and dashboard HTML with `Cache-Control: no-cache, must-revalidate`, retaining ETag and Last-Modified validators. The policy follows the selected HTML file, including a single-page fallback, while non-HTML build assets keep their existing file-response behavior. This requires revalidation on future navigations; it does not replace JavaScript already running in an open tab. The Web Demo remains served by its separate protected container.

Routers separate accounts, user profile, API keys, content, Web Demo, admin tools, superadmin tools, public publishing/reading, the game's accounts and characters, health and frontend delivery. `dependencies.py` authenticates sessions and keys and checks database-backed access. A hidden frontend button is never the authorization boundary.

Services own storage adapters, knowledge persistence, Whole-book upload, graph sidecars, email, Qdrant access and semantic discovery. `database.transaction()` opens a PostgreSQL connection, commits on success and rolls back on error. External vector/image writes do not share that transaction; see [ingestion](../ingestion.md).

`routers/news.py` handles personal subscriptions, authorized email preview, unsubscribe confirmation and verified provider events. `services/news.py` owns explicit consent, the publication outbox, Resend delivery retries and suppression; `services/email.py` renders all four email types. The optional lifespan worker uses PostgreSQL leases and saved provider idempotency keys. [News subscriptions](../news-subscriptions.md) owns API behavior and delivery limits.

`services/media_creation.py` wraps editorial creation in a persistent request identity scoped to its editor. The response and normalized payload fingerprint commit with the post and any announcement, so a lost creation response can be retried safely. Conflicting reuse returns 409; creating an announcement requires a UUID while legacy news-only creation remains compatible.

`routers/game.py` serves UMST under `/api/game`: a password sign-in that makes the game's key, character calls that take a regular key and re-check it inside their transaction, and since 0.0.16 the list of grimoires, whole books and the Web Demo's notes, counted as `book` and, apart from the list, behind Web Demo access. Its refusals answer `{code, detail}`, and `install_error_handlers` gives request validation the same shape, always with `errors`, on game paths only. A router dependency reads the optional `X-Install-Id` header before anything else, and the leases compare installs as well as keys. `authenticate_api_key(request, kind=..., master_allowed=..., access_point=...)` counts each key request as `book` or `character` and can refuse master keys before counting. With `access_point` it raises `AccessRefused` for a regular key whose account lacks that access point. It reads the account's access points from the authority map `current_user` reads for a session. `main.py` answers the refusal as 403 `{code: "<access point>_access_required", detail}`. `routers/public_api.py` asks for `demo` on its book reads, and its book images also take a session with that access. `services/api_keys.py` makes regular keys, including the Default key that `POST /api/api-keys/default` makes for the signed-in API Keys page, and revokes game keys on sign-in and password reset. `services/sign_in_attempts.py` checks passwords for the game's sign-in and the website's `/auth/login` alike and slows repeated wrong passwords per account and address under advisory locks; the login runs that check in a worker thread. A successful password reset clears the account's count through it, in the reset's transaction. [Game accounts](../game-accounts.md) owns the API and the limits.

Web Demo routes require the Web Demo access point. Since 0.0.13 book reads under `/api/v1` require it too, from a key's account or, for book images, from a session. Master keys keep their reads. Reader queries filter book visibility and active knowledge. Personal writing belongs to its user independently of source availability. Publishing and administration retain their own authorized routes. Read [security](../security.md) before changing these distinctions.

`services/book_read.py` builds, stores and checks a book's whole-book reads: `book_read` for the Web Demo and, since 0.0.16, `book_game_read` for the game. Whole-book upload and `services/knowledge.py` call it inside their transactions, the upload's `_finalize_images` once more for the game row after the images, and `python -m scripts.build_book_reads` for the books already held. `routers/demo.py` and `routers/game.py` serve the stored rows without reading the book again, through the module's shared ETag, gzip and caching helpers. [Data architecture](data.md) owns the answer and [Web Demo behavior](../web-demo.md#whole-book-read) the route.

Schema source lives in `backend/sql`. `reviewed_migrations.py` checks file hashes, baseline markers, applied schema markers and partial application. The explicit migration runner requires a verified backup digest. Backend lifespan calls the readiness check by default; historical replay is restricted to an explicitly configured local environment. [Operations](../operations.md) owns commands.

The [backend README](../../backend/README.md) lists source entry points. [Test modules](../../backend/python/tests/README.md) explain actual service/database coverage.
